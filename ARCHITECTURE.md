# Project Architecture

## Overview

CV-Val is a Vite-based React application that targets web, Electron desktop, and Capacitor mobile builds from a single codebase.

The current codebase is organized around three top-level layers:

* `@apps` for product-level screens, feature orchestration, and app-specific bridges
* `@packages` for reusable analysis and panel-layout primitives
* `@shared` for UI primitives, utilities, and cross-app helpers

## Current Structure

```text
src/
  main.tsx          # React bootstrap
  App.tsx           # Hash router + platform bridges
  _legacy/          # Older page implementations kept for reference

@apps/
  pages/            # App shell and top-level pages
  features/         # Domain features such as pose, ball, and bat
  common/           # App-specific bridges and handlers

@packages/
  cv-val/           # Core data, detectors, hooks, and modules
  panel-layout/     # Generic panel layout system

@shared/
  bridges/          # UI bridge abstraction
  components/       # Shared UI components
  utils/            # Shared utilities
  service/          # Media / export helpers

public/
  external/models/  # Runtime model assets
  guide/            # Markdown guides
  *.md              # Home page content blocks
```

## Design Notes

* `AppPage` is the current composition root for the main product UI.
* `FeatureRegistry` acts as the feature wiring layer for detectors, analysis tools, and modules.
* `src/_legacy/pages` should be treated as historical or fallback code unless a migration explicitly targets it.
* `public/external/models` is large by design because model assets are loaded at runtime by the browser/Electron app.

## Data Flow

1. A user loads a video or analysis file through `AppPage`.
2. `useAppLogic` routes the file by extension and delegates video decoding or data loading.
3. `useProcessor` wraps `Processor` and exposes processing status, progress, and errors to React.
4. `Processor` converts video frames through `MediaBunnyVideoToImageList`, initializes the selected detector, and writes feature data into `CVValData`.
5. `CVValData.set()` stores primary analysis data, moves raw frame ownership into `CVValImageListManager`, and runs registered secondary analysis tools.
6. Panel modules receive the current `CVValData` and `currentFrame` from `PanelModuleContainer`.

## Module Lifecycle

Panel modules implement the `AnalysisModule` contract from `@packages/cv-val/types/analysis-module.ts`.

* `View` renders the runtime output for the current frame.
* `Settings` renders module-specific controls.
* `defaultSettings` seeds per-instance settings.
* `init` and `cleanup` are optional hooks for resources such as WebGL scenes or loaded plugins.

`ALL_AVAILABLE_MODULES` in `@apps/FeatureRegistry.ts` is the current registry for built-in modules. New modules should be registered there after their feature-local implementation is added.

## Save Formats

Feature data files use feature-specific extensions:

* `.cvp` for pose data
* `.cvbl` for ball tracking data
* `.cvbt` for bat tracking data

Unified `.cvval` files are serialized by `CVValFileHandler` as:

```text
[Header Size (4 bytes)][Header JSON][Video Blob][Analysis Blob...]
```

The header includes format version, video metadata, video blob size, and ordered analysis blob descriptors. Loading reverses this layout, restores video frames through the processor video loader, and rehydrates feature data through the matching `FeatureRegistry` entry.

## Practical Guidance

* Add new feature-specific code under `@apps/features/<domain>` when it belongs to a product flow.
* Add reusable analysis or layout primitives under `@packages`.
* Add generic UI and utility code under `@shared`.
* Prefer updating `FeatureRegistry` and the domain feature folder together when introducing a new analysis feature.
* Keep generated platform output out of broad tooling runs unless the task specifically targets those outputs.

## Platform Validation Matrix

| Area | Web | Electron | Capacitor Mobile |
| --- | --- | --- | --- |
| Video open | Browser file picker through hidden file input | Renderer picker plus main-process external file bridge | Native WebView file input after Capacitor sync |
| Analysis open | `.cvp`, `.cvbl`, `.cvbt`, `.cvval` through file input | Same extensions plus OS file association path through `electron/main.ts` | Same web flow after mobile build |
| Save | File System Access API when available, fallback IPC in Electron | `save-file-dialog` IPC handler writes selected path | Browser/WebView download or platform picker support must be checked per device |
| Native menu | Not applicable | `update-native-menu` IPC builds per-window menu | Not applicable |
| Generated folders | Not present | `out/**` is generated by electron-vite | `android/**`, `ios/**`, and `expo-app/dist/**` are generated or platform output |

## Build Asset Notes

Current runtime model assets under `public/external/models` contain 272 files and occupy about 1.0GB. A web build copies those assets into `dist`, so the current `dist` folder is also about 1.0GB. The JavaScript entry chunk is about 2.6MB minified and currently triggers Vite's 500kB chunk-size warning.

## Feature Registry Loading

`FEATURE_REGISTRY` currently creates detector instances when `@apps/FeatureRegistry.ts` is imported. The heavy model files are still loaded later by each detector's `initialize()` method, but the registry eagerly allocates detector wrapper objects for every built-in model. If startup time or memory becomes an issue, the next structural improvement should be to replace detector instances with small factory functions while keeping the same UI model labels.

## Structure Cleanup Decisions

`src/_legacy` is excluded from lint and should remain read-only reference code until a specific migration or removal task is approved. New work should target `@apps`, `@packages`, and `@shared`.

`@shared/components/ui-brick` owns reusable React UI primitives and theme variables. The root `style/` CSS files provide global layout, navigation, and visual skin styles. New component-level styling should stay with the component or UI bridge unless it is genuinely global page chrome.
